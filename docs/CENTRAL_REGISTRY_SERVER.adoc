= MCDF Central Registry Server
:toc:
:toclevels: 3

== Purpose

The MCDF Central Registry Server is the uniform upload and archival endpoint for MCDF Manager.

The desktop client sends MCDF uploads to one HTTPS endpoint, such as:

----
https://mcdf.thebigtree.life
----

The server validates the MCDF, extracts every internal full file, stores those extracted files as the durable archive unit, writes a rebuild manifest, and can publish the resulting artifacts to GitHub Container Registry as OCI artifacts.

The original `.mcdf` upload is treated as temporary input. The long-term source of truth is:

* extracted full internal files;
* a rebuild manifest;
* immutable hashes;
* optional OCI references in GHCR.

This avoids keeping a backup of the package container as the main backup. The durable backup is of the full files inside the package.

== Binary

The repository now builds two deliverables:

* `mcdf-marketplace` — the Tauri desktop client.
* `mcdf-registry-server` — the central/local registry server.

Both are built by GitHub Actions release workflow for Linux, Windows, and macOS where supported.

== Local test mode

Start a local registry server:

[source,bash]
----
mcdf-registry-server \
  --bind 127.0.0.1:8080 \
  --public-url http://127.0.0.1:8080 \
  --data-dir ./mcdf-registry-data \
  --storage-mode local
----

Then in MCDF Manager, open Settings and use:

----
http://127.0.0.1:8080
----

Use *Check server* to verify the connection and *Upload test MCDF* to test archival.

== Hosted mode

For a hosted server behind a reverse proxy:

[source,bash]
----
mcdf-registry-server \
  --bind 0.0.0.0:8080 \
  --public-url https://mcdf.thebigtree.life \
  --data-dir /var/lib/mcdf/data \
  --storage-mode ghcr-oras \
  --server-auth-token '<upload-token>' \
  --ghcr-owner thebigtree \
  --ghcr-package-prefix mcdf \
  --ghcr-username '<github-user-or-bot>' \
  --ghcr-token '<github-token-with-package-write>'
----

The desktop client should receive only the server upload token if uploads are protected. It should never receive the GitHub/GHCR token.

== Environment variables

Every CLI option can be supplied through an environment variable:

[cols="1,1,2"]
|===
|Option |Environment |Purpose

|`--bind`
|`MCDF_SERVER_BIND`
|Socket address to listen on. Use `0.0.0.0:8080` behind a reverse proxy.

|`--public-url`
|`MCDF_PUBLIC_URL`
|External URL used in manifests and API responses.

|`--data-dir`
|`MCDF_DATA_DIR`
|Persistent storage directory for file artifacts and rebuild manifests.

|`--server-auth-token`
|`MCDF_SERVER_AUTH_TOKEN`
|Optional bearer token required for upload calls.

|`--storage-mode`
|`MCDF_STORAGE_MODE`
|`local`, `ghcr-dry-run`, or `ghcr-oras`.

|`--ghcr-owner`
|`MCDF_GHCR_OWNER`
|GitHub user or organization that owns the GHCR packages.

|`--ghcr-package-prefix`
|`MCDF_GHCR_PACKAGE_PREFIX`
|Prefix for GHCR packages. Defaults to `mcdf`.

|`--ghcr-username`
|`MCDF_GHCR_USERNAME`
|Username used for ORAS login.

|`--ghcr-token`
|`MCDF_GHCR_TOKEN`
|GitHub token/PAT with package write permissions.

|`--oras-bin`
|`MCDF_ORAS_BIN`
|Path to the `oras` executable.
|===

== Storage modes

=== local

Stores extracted full files and rebuild manifests in the local data directory only.

Use this for local development, CI tests, and safe end-to-end validation with private MCDF files.

=== ghcr-dry-run

Stores locally and calculates the GHCR references that would be used, but does not push.

Use this to validate naming and metadata without writing to GitHub.

=== ghcr-oras

Stores locally and uses an installed `oras` binary to push each file artifact and manifest artifact to GHCR.

Generated references look like:

----
ghcr.io/<owner>/<prefix>-files:<file_hash>
ghcr.io/<owner>/<prefix>-manifests:<package_hash>
----

== API

=== Health

[source,http]
----
GET /v1/health
----

Returns server health, public URL, storage mode, GHCR configuration state, and whether uploads require auth.

=== Registry status

[source,http]
----
GET /v1/registry/status
----

Returns local package/file artifact counts and current registry configuration.

=== Probe package

[source,http]
----
POST /v1/packages/probe
Content-Type: application/json

{ "package_hash_blake3": "..." }
----

Returns whether a package manifest is already known.

=== Upload package

[source,http]
----
POST /v1/packages/upload
Content-Type: application/octet-stream
X-MCDF-Filename: example.mcdf
Authorization: Bearer <optional-upload-token>

<raw mcdf bytes>
----

The server parses the upload, extracts internal files, stores each extracted full file by BLAKE3 hash, writes a rebuild manifest, and optionally pushes artifacts to GHCR.

=== Read manifest

[source,http]
----
GET /v1/packages/{package_hash}/manifest
----

Returns the rebuild manifest.

=== Download rebuilt package

[source,http]
----
GET /v1/packages/{package_hash}/download
----

Rebuilds the MCDF from archived full files, verifies the rebuilt package hash, and returns the MCDF bytes.

== End-to-end local test

The helper script builds the server, starts it in local mode, uploads a test MCDF, reads the manifest, downloads the rebuilt package, and compares hashes when Python `blake3` is available.

[source,bash]
----
./scripts/local-server-e2e.sh /path/to/test.mcdf
----

== Container deployment

A simple server container can be built from `Dockerfile.server`:

[source,bash]
----
docker build -f Dockerfile.server -t ghcr.io/thebigtree/mcdf-registry-server:dev .
docker run --rm -p 8080:8080 \
  -e MCDF_PUBLIC_URL=https://mcdf.thebigtree.life \
  -e MCDF_DATA_DIR=/var/lib/mcdf/data \
  -v mcdf-registry-data:/var/lib/mcdf/data \
  ghcr.io/thebigtree/mcdf-registry-server:dev
----

For production, place it behind TLS termination on port 443.
